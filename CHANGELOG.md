# Changelog

All notable changes to the Progena AI project (formerly Progenitor) will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- **Message usage and completed work**: live replies use provider-reported output rather than text-chunk counts, with a styled response/intermediate/final-call breakdown and honest unknown/zero values. Completed reasoning/tool activity is one outer disclosure with the existing summary-row style; detailed headings, delegated-agent cards and conversation-summary markers remain available. Provider interruptions and real failure/cancellation states survive transport completion. Legacy scratch-cache frame counts are invalidated without deleting messages.
- **Chat history performance**: summary-bearing reads use one compact native checkpoint index instead of repeatedly loading every channel at every historical checkpoint. Message-only snapshots preserve native DeltaChannel replay, revision isolation, nested summaries and commit times. A single lossless runtime message transfer replaces repeated internal item-page replays without changing browser paging or SSE. Read-only measurements on the affected production conversation reduced cold backend detail from 9.34 seconds to a 0.50-second median, with identical payloads and no timeout increase.
- **Channels page and document-driven channels**: the Channels page is now live instead of mocked. Each messaging channel is a `channel:<id>` JSONB state document (`channel.schema.v1.json`) holding its type, enabled flag, settings and credential references; Telegram is the first channel type. The page lists real channels with live connection status, bot handle, message counts since backend start and the session ids of conversations through the channel, filtered as Started/Stopped/Errored. Header actions start/stop, reconnect and send a test message; the settings form is generated from the type's field descriptors, and the bot token comes from an environment variable or is stored encrypted with `PROGENA_PROVIDER_ENCRYPTION_KEY`. Changes from any writer reconnect the channel automatically. New channel types plug in through a `ChannelTypeSpec` + `ChannelAdapter` in `src/backend/channels/`. The agent can read channels at `/config/channels/<id>.json` (credentials redacted), workflows can react to `channel` documents, and chat session summaries now include their `source`. Channel event names and the channel document prefix live in the shared contracts. **Migration**: on first start the existing `TELEGRAM_*` variables seed `channel:telegram` (the token keeps coming from `TELEGRAM_BOT_TOKEN`); afterwards the other `TELEGRAM_*` variables are ignored and the backend Telegram settings were removed from `ChatServerConfig`. Telegram code moved from `src/backend/integrations/` to `src/backend/channels/telegram/`.
- **Shared behavioural contracts**: app SSE names and routine lifecycle categories now share a packaged Python/browser vocabulary. Queue keys, checkpoint identity construction, window events, quick-chat modes and workspace-local storage keys have canonical owners; existing wire values, stored IDs and global preferences are preserved.
- **Read-only mount search limits**: explicit SDK `grep`/`agrep` signatures preserve `max_count` through public read-only and Composite mounts. Limited Runs searches stop hydration when truncation is known instead of materializing every matching run before trimming the result.
- **Runs infinite navigation**: virtualized infinite scrolling replaces page controls, with in-chart loading/retry/end states and stable live inspection. Search sits at the right; kind/status filters live in styled header popovers, Started/Duration headings control global ordering, and the sliding time capsule remains in the toolbar. Filters, sorting and inline selection remain URL-backed.
- **Runs review fixes**: live arrivals and snapshot refreshes retain loaded cursor-boundary rows; virtual scrolling retains selected calls, collapsed branches and open details. Resumed routine attempts isolate timing and usage on shared threads and receive checkpoint updates. Resolved workflow approvals no longer block manual Resume after a child routine finishes.
- **Runs canonical event recovery**: reconnect snapshots replace cached records while preserving in-flight updates and inspection state. Initial trace hydration observes checkpoint notifications; wired workflow steps record their actual conversation before execution. Historical activity uses recorded audit kinds, and workflow search matches lowercase semantics across Postgres and memory.
- **Runs execution consistency**: lifecycle updates supersede obsolete checkpoint rows; initial GET and nested-child hydration observe existing invalidations. Failed/cancelled routine steps retain trace threads, nested subagent usage includes all delegation levels, and interrupted records without terminal events show unknown completion/duration rather than fabricated zeroes.
- **Runs failure and retry consistency**: schema-rejected routine outputs retain their trace thread; compact summaries consume audit threads and recorded execution kinds like expanded traces. Authoritative hydration retries preserve replacement semantics, offscreen expansion changes discard stale virtual heights, and off-page selected runs expose loading/errors/retry instead of a blank chart.
- **Agent run-log consistency and bounded reads**: `/runs/` uses full run IDs in virtual filenames (no short-ID aliases), exact persisted child invocations and historical workflow audit kinds/threads, including failed steps with cleared outputs. Compact storage projections and bulk title maps replace full-history payload scans and per-title lookups; single-file reads load only the selected run and related lifecycle threads. Equal-time runs sort deterministically, interrupted terminal logs are cached without stale Continue links, and all run kinds expose recorded token components with unknowns preserved and descendant usage counted once.
- **Agent run-log freshness and search isolation**: virtual grep filters paths and SDK glob patterns before hydrating file content. Terminal run caches validate compact checkpoint revisions across related threads and namespaces, and reject renders raced by checkpoint updates. Repeated agent nodes show only their own execution windows. Full run IDs remain authoritative when filenames contain an earlier title, timezone date or queued date; no short-ID compatibility paths are added.
- **Agent native-contract and concurrency fixes**: workflow logs use full persisted outputs rather than bounded audit summaries and retain every child attempt across approval resumes. Pending native child invocations expose completed work before parent nodes return, without duplicate child speech or usage. Scheduled `error` records retain their explanations. Cache mutation is safe across overlapping readers; consumed definitions/preferences invalidate stale views, and compact lifecycle snapshots avoid reloading terminal outputs on hits. Exact-file grep/glob honor durable full-ID paths, while limited grep stops hydration once truncation is proven.
- **Runs execution viewer**: Spectate now has a compact flame-chart grid for workflows, routines and schedules. Entire run rows expand by click or keyboard; estimated step counts and the bottom legend are removed. Runs and structural parents show overlapping activity summaries; sibling model calls and untimed tool markers share dense lanes. Recorded token columns populate from compact audits and selected routine checkpoint tips, then expand to per-model usage without double-counting parent totals. Separate row disclosures reveal input/output/error details. Design-library controls and unclipped styled tooltips expose run identity, trigger, timestamps, existing schedule request context and loaded failure reasons. Compact workflow-definition projection avoids transferring prompt/config bodies repeatedly. One chart scrollbar and sticky headers keep the page fixed. Push events update runs and subscribed activity without polling or Refresh. Model timing remains checkpoint-derived; tools use measured audit durations or explicit unavailable markers. Workflow audit starts are persisted before execution and retained through approval/child-routine waits.
- **Runs as readable logs (`/runs/`)**: the agent can now read what routines, workflows and schedules did. Each top-level run is one read-only `/runs/{routines,workflows,schedules}/<date>_<slug>_<run_id>.md` file in the same IRC style as `/sessions/`: the trigger as a topic (only the fields that changed), one line per step, agent and model replies in full, child routine runs inlined, and the reason a run failed, stopped or was interrupted. Long data shows both ends and a pointer to the whole value (a mount path or `<file>#<n>`). Rendered from existing records on read, so past runs appear with no backfill. `run_workflow` now returns the run's `run_id` and its `/runs/` path.
- **Chat tool results keep both ends after reload**: a long tool result restored from history now shows its first and last 200 characters around `… ⟨N KB omitted⟩ …` instead of only the first 400, so conclusions and exit-code footers stay visible.
- **Routine Stop / Resume / Cancel**: the existing toolbar icon now stops an owned native graph execution, resumes its exact checkpoint, or offers Cancel after five seconds still stopping. Cancellation permanently closes that logical session without deleting history. Pending and terminal controls survive UI reconnects, nested stops unwind the parent safely, and workflow waits distinguish stopped/cancelled from successful completion. Unknown execution ownership is reported rather than guessed; external work and side effects are not rolled back.
- **Live delegating chat status**: canonical chat response activity distinguishes a parent response that is generating from one waiting on synchronous routine/subagent, A2A, or ACP work. The selected chat restores that transient status after reload; completed, failed, and cancelled responses clear it. Header, sidebar, and navigation indicators show Delegating without changing composer or cancellation behavior.
- **Readable authored graphs**: routine/workflow skills now require short purpose-based node labels/titles, stable identifiers, and saved non-overlapping workflow positions. Layout guidance covers branch lanes, port-aware card sizes, viewport zoom, readback/visual checks, and the distinction between workflow canvas positions and topology-driven routine chains.
- **Shared Quick Chat transcript**: Quick Chat now uses the main conversation renderer and live-turn model rather than separate Markdown bubbles. Reasoning/work groups, paired tool I/O, todos, subagent/A2A cards, attachments, typing, and context usage survive streaming, reload, and promotion to the chat page. Both surfaces reuse transcript scroll anchoring; Quick Chat retains its separate thread and page-context lifecycle. Its New chat action uses a plus icon rather than a refresh arrow.
- **Shared transcript ownership**: the common `ChatMessages` renderer now owns row-height observation for both chat surfaces. Filter metadata/defaults and whole-call visibility are centralized in the existing filter model, while Quick Chat subscribes only to live-turn presence outside the streaming renderer.
- **Chat context-window pie**: a compact filling circle sits immediately left of voice when the matched model profile declares a positive-integer `context_window`. Hover shows the latest parent-model call's input-plus-output footprint and capacity. Live usage and reloaded history retain this separately from accumulated billing tokens; missing capacity, unknown usage, or an ambiguous/switched model keeps the indicator hidden.
- **Profile cache-expiry countdown**: both chat composers show bold remaining time immediately left of the context pie when the matched profile declares `cache_ttl_seconds`. Successful replies reset the estimate; saved history uses persisted timestamps instead of restarting on reload. Missing duration/timestamps hides it, expired estimates show `0m`, and the tooltip makes clear this does not observe or configure actual provider caching.
- **Consistent composer tooltips**: voice, attachment, send/stop, context usage, and cache countdown controls share the same styled hover/focus treatment. Disabled action wrappers remain keyboard-focusable for explanations, and right-side tooltips stay inside the viewport.
- **Compact chat turns**: work is grouped by reasoning summary, with paired tool Input/Output disclosures, plan checklists, and persisted reasoning/commentary on reload. Active groups show every tool call with an expanded chevron; they collapse when the answer starts, and remain reopenable. Subagent/A2A cards retain their separate latest-three-entry previews and full-history toggle. Pending status words, active work, and the streamed answer keep a gutter dot with gentle fading/color activity until completion (static with reduced motion). Both chat surfaces share scroll anchoring: work follows the tail unless the user scrolls away, and long answers keep their beginning visible through work collapse and completion.
- **Routine Code node**: run inline JavaScript directly in a fresh QuickJS/Wasm sandbox without an LLM call. The routine editor includes a Code step, syntax-highlighted source field and graph-value autocomplete that inserts JavaScript-safe `input` references. Scripts receive routine data as `input` and return a JSON-compatible value under the node's output key. Execution is bounded to a 16 MiB heap, 512 KiB stack, one-second JS deadline and 1 MiB serialized result. Host tools are disabled by default.
- **Scoped filesystem tools for Code nodes**: explicitly enable read-only or read/write access to selected `/artifacts/` and `/shared/` subtrees. Sandboxed scripts can read/search files and, with write permission, write, edit, copy, move or delete text files through existing backend validation. Tool-enabled nodes never cache or automatically retry. Existing destinations are rejected for writes/copies/moves; moves are non-atomic copy/delete within a single mount. No shell, network or agent tools are exposed.
- **Local JavaScript execution**: the main Progena agent can write and execute JavaScript through Deep Agents' official QuickJS middleware, using QuickJS-NG compiled to Wasm and local Wasmtime. Scratch variables last only for the current turn, with a 64 MiB JS heap, five-second JS execution limit and bounded result/console output. An explicit bridge allows file reads, registered A2A communication and live object-agent/routine dispatch; direct writes, shell and arbitrary network access remain unavailable. Bridge operations bypass individual parent approvals, and delegates retain their own existing permissions. No commercial sandbox service is required. Existing saved genesis instructions remain user-owned; review older code-execution restrictions through the Instructions page.
- **ChatGPT plan model provider**: supported local Sign in with ChatGPT using dynamic registration, PKCE and signed identity validation; protected SSH-transferred credentials import into encrypted server storage with rotating refresh and distinct registrations. A plan-disabled connection can explicitly repeat consent with `sign-in --reauthorize --enable-plan-usage`, while ordinary reauthorization remains consent-free. Settings exposes account status, available models, testing and disconnect. Chat and auxiliary calls use stateless streaming Responses, application-managed tool/history replay, and no unsupported temperature/output-token controls; existing Foundry/OpenCode connections retain their behavior. ChatGPT token counts are not priced as API charges.
- **Configurable agent name** (Settings → General → Agent name, `agent_name` in `/config/preferences.json`, default `Progena`): the UI labels the agent's messages, prompts and actions with it, and runtime instructions may use an optional `{agent_name}` placeholder (the bundled `genesis.md` does). Display only; identifiers are unchanged.
- **Shared exchange volume**: setting `PROGENA_SHARED_DIR` mounts that directory as a writable `/shared/` route for the agent. Compose mounts the external `progena-shared` volume there, and deployment creates it, so A2A agent containers that mount the same volume can exchange files with Progena. Startup fails when the configured directory is missing.
- **Chat file deletion with declared mount access**: the main agent's `delete` tool removes single files. `MOUNT_ACCESS` (`src/progena/agent/filesystem/mounts.py`) declares every mount as `read`, `read-write`, or `read-write-delete`; deletion is allowed only under `/routines/`, `/workflows/`, `/tasks/`, `/instructions/`, `/canvases/`, `/artifacts/`, `/shared/`, and scratch state. Directories (including empty ones and mount roots), `..` paths, runtime `progena/` instructions, and undeclared mounts are refused. The agent's scratch `files` state channel is preserved. The tasks skill now names the real `delete` tool instead of the nonexistent `delete_file`.
- **Object and list literals in routine expressions**: `eval`/`condition`/`switch` expressions accept JSON-style `{...}` and `[...]` literals with `**` mapping unpack, e.g. `{**card.metadata, "review_approval": {"inbox_id": inbox.id, "sha": evidence.commit_sha}}`. Keys must be strings, `**` unpacks only objects, entries merge left to right (later keys win), and the result is a new object that never mutates state. Constructed collections are capped at 100,000 logical entries (shared references count every time they appear), and each evaluation may build and compare at most 1,000,000 logical entries in total, with nesting and AST depth limits, so repeated or deeply compared literals cannot stall the runtime; calls, subscripts, comprehensions, imports, `*` unpacking, `eval`/`exec` and non-object attribute access stay rejected.
- **Inbox message `refs` port**: inbox messages gain an optional generic `refs` object (default `{}`), exposed as a writable `document_create` workflow port. Workflow authors may store immutable candidate bindings there; user-owned fields are unchanged.
- **Manual workflow triggers**: workflows can now be on-demand-only. A `manual` trigger declares typed payload output ports, applies property defaults, and is preferred for browser and `run_workflow` runs when event/cron triggers also exist.
- **Interrupted runs after a runtime restart**: chats, scheduled runs and routine runs cut off by a runtime restart now say so instead of looking idle or still running. Detection is read-only: the backend reads the LangGraph checkpoint directly, compares its `runtime_instance` owner to the live health identity, and excludes steps waiting on a person or failed turns. A backend-only restart never counts.

### Fixed
- **Resumed async task cards**: check/list observations of running tasks now emit correlated progress updates, clearing stale “Awaiting approval” state after a resume.
- **Chat constant ownership**: UI request source metadata uses the canonical backend HTTP contract, and live cancellation rendering reuses the frontend cancellation suffix constant without changing stored values or adding duplicate suffixes.
- **Contract-only frontend deployments**: shared event vocabulary and imported routine-schema changes now trigger a frontend image rebuild.
- **Async delegation visibility and approval pauses**: tracked async tasks render as Delegations instead of hidden Debug events, retain one card across pause/resume/result, and preserve result-only replay. Human-approval interruption is nonterminal.
- **Chat mutation acknowledgements**: metadata/deletion events retain causal request IDs through durable dispatch; successful empty/idempotent PATCHes acknowledge a correlated snapshot without inventing a document change.
- **Tool failure transcripts and plugin HTTP errors**: transcript actions use canonical tool-failure classification. Plugin routes use typed failures, distinguishing ordinary forbidden responses from rate limiting rather than parsing error wording.
- **Shared workflow/canvas contracts and deployment metadata**: workflow terminal events, workflow-run prefixes and canvas iframe messages have canonical definitions. Removed unused Copilot environment settings and corrected the runtime image's exposed port to 9501.
- **Reserved routine node IDs**: editor validation now reads the persisted schema's reserved-ID list, rejecting `__project_output__`, `__start__` and `__end__` before saving as well as `__seed__`.
- **Backend health-test isolation**: each backend test starts without a shared lifecycle client, preventing parallel worker order from leaking a running client into unrelated state-reader tests. Missing-document health coverage now explicitly checks unconfigured, unreachable and reachable runtimes; production health behavior is unchanged.
- **Parallel Postgres event tests**: committed-event assertions wait only while the existing deferred-event query reports a cluster-wide transaction watermark blocker, including transactions in another worker's database. Open-transaction ordering, rollback and no-lost-event assertions remain strict; production dispatch is unchanged.
- **Agent progress updates vanishing in chat**: text the agent writes just before a tool call is moved off the answer onto that call, where it showed only as the call's one-line, ellipsis-truncated summary, so a streamed update seemed to disappear when the next tool started. It now renders in full above the tool row, and the row summarises the call's input.
- **Object-agent shells can create temporary files**: the scrubbed shell environment had no `TMPDIR`, so `mktemp` and similar tools fell back to `/tmp`, which is read-only in the hardened runtime container. Shells now inherit a nonempty runtime `TMPDIR` without needing `env_passthrough`, or use their agent home when it is unset. Runtime Compose sets `TMPDIR=/app/tmp`, the existing writable `noexec` tmpfs, so temp files are bounded and volatile and cannot be executed. Read-only and other hardening settings are unchanged.
- **Stopping a routine run cut off by a runtime restart**: Stop on a run left `started` by an earlier runtime process returned 409 because no task owned it. Each `started` lifecycle now records its runtime process; Stop settles such a run as `stopped` so Resume continues its last checkpoint, and Cancel closes it. Runs owned by the live process are never inferred dead.
- **Heartbeat thread poisoned by task completions**: completed A2A, ACP, and async-subagent tasks no longer write a synthetic tool result into the heartbeat loop's own thread. Those results had no matching model tool call, so OpenAI rejected every later model call on that thread (`No tool call found for function call output`). The originating thread still receives its completion follow-up and the audit log still records the result. A model-request guard now drops any tool result without an earlier matching tool call and logs the dropped ids, which also restores threads that already contain such results; saved history is not rewritten.
- **Theme-aware chat code blocks**: fenced text and code use the active theme's foreground and background instead of keeping a dark surface with light-mode text. Light-mode syntax tokens and diff highlights use contrast-adjusted theme colors; dark-mode syntax colors are preserved. Both Quick Chat and conversation history share the fix.
- **Bounded alert text**: alert lists show up to three preview lines. Selecting an alert preserves its full content in a scrollable detail area capped at 320px or 40vh.
- **Work-collapse scroll anchoring**: a new long answer remains anchored near its beginning even if a tall tool list collapses immediately after the user scrolls back to the bottom.
- **Complete failed-call rendering**: Errors retains the full invocation (input, filename, and commentary) even with Tools hidden, and recognizes returned execute/JavaScript failures consistently with tool output. Planning calls that fail after producing a checklist retain their error detail and error marker. Merged tool outputs preserve authoritative artifact summaries, including omitted-line explanations.
- **Quick Chat promotion survives full storage**: rich image/trace payloads stay in the in-memory handoff, while a single reload fallback keeps at most 100 persistable messages without duplicated timeline images. Storage quota/access failures no longer prevent opening the chat, and the canonical thread ID survives reload.
- **Failure classification survives truncation**: tool results are classified from their full text before preview truncation (`tool_result_failed`), so a long failing `execute`, a thrown JavaScript error, an error-status message, or a non-zero `exit_code` artifact sets `success: false` live and `failed: true` in reloaded history. Subagent nested results use the same classification, so Errors and the card's failed count include returned nested failures.
- **Quick Chat promotion keeps failed partial answers**: the in-memory handoff keeps its rich timeline instead of rebuilding from `content`, so a partial answer before a failure survives "Open in chat". Storage reload still rebuilds from persisted fields.
- **Consistent cache countdown start**: live turns start the countdown only for completed replies with answer text, matching reloaded history; tool-only or empty turns no longer start it.
- **Visible focus on delegation cards**: subagent and A2A card toggles show an accent focus ring for keyboard focus.
- **Quick Chat refresh integrity**: reopening loads every history page rather than replacing cached history with only the newest 50 messages. A monotonic epoch invalidates delayed refreshes when a new submission starts, preventing an older snapshot from overwriting the newer completed turn.
- **Chat rendering/history review fixes**: saved task delegations retain their commentary; failed or unrepresented `write_todos` calls remain visible and count toward work failures without duplicating successful plan previews. Headed reasoning groups retain authoritative provider summaries/details, standalone plan disclosures have accessible names, and completed work duration uses the first nonempty answer boundary. Non-chat review findings are tracked in `docs/REVIEW_FOLLOWUPS.md`.
- **Chat auto-scroll**: sending re-enables following even when scrolled back. New short replies and live work follow the bottom; once the newest answer exceeds the available viewport, its start stays near the top through streaming and the saved-message handoff. Manual scrolling releases that reading position without being pulled back by later updates. Entry slide-in animations no longer shift the scroll target.
- **Routine Code filesystem failures remain actionable**: sandboxed Code nodes now expose scoped filesystem errors to JavaScript `catch` blocks through `error.message` without leaking unexpected host failures, and `writeFile` refuses an existing destination instead of overwriting it.
- **Code node writes into new directories**: `writeFile`, `copyFile` and `moveFile` accept a destination whose parent directory does not exist yet on filesystem-backed mounts such as `/shared/`. The destination guard now treats Deep Agents' `path_not_found` listing code as absence instead of rejecting the write.
- **Provider encryption key reaches production**: the deploy step now passes the `PROGENA_PROVIDER_ENCRYPTION_KEY` environment secret to Compose, which database-stored provider credentials (including ChatGPT plan OAuth tokens) require. The ChatGPT credential import recipe streams the file into the runtime tmpfs as its unprivileged user because `docker cp` cannot write there.
- **Cross-provider reasoning replay**: Responses API checkpoints now attribute opaque reasoning and response IDs to their provider connection. A later turn preserves them only for the same connection (falling back to matching provider kind and base URL); provider switches and legacy checkpoints with unknown origin drop opaque items while retaining visible assistant text and tool calls.
- **JavaScript bridge compatibility**: retain standard nullable `anyOf` schemas during metadata compaction so the interpreter can render read/A2A tool signatures without crashing. JavaScript subagent calls now use the same live object-agent/routine resolution as normal task calls, including targets added after graph compilation.
- **Module catalogue included in deployment images**: allow bundled `data/modules/` through the Docker build context and include catalogue changes in both Python-image rebuild decisions. This fixes the missing-directory `COPY` failure and keeps manifest validation aligned with deployed libraries.
- **ChatGPT token recovery**: preserve a rotated refresh credential before deferred ID-token verification, retry that validation without replaying its consumed grant, and retry one pre-output HTTP 401 with a coordinated token refresh. Reasoning replay now retains the completed status, streamed summary and encrypted content without duplicate chunk fields.
- **ChatGPT structured and auxiliary calls**: recover completed Responses output items from the stream when the ChatGPT plan terminal event reports an empty `output`, restoring schema-constrained output and tool follow-ups.

### Removed
- **Obsolete root scripts retired**: removed the obsolete diagnostics, live evaluators, helper, and one-off migration utilities with their live-evaluation reports. Retired scripts remain available in Git history.
- **Obsolete Git skill removed**: repository setup and publication remain with `repo-manager`; removed the legacy build-loop Git instructions.
- **Empty bundled MCP scaffold removed**: removed `app/mcp/`, its unused deployment workflow and directory-scanning registry/listing fallback. External HTTP MCP discovery, invocation and persisted configuration remain supported.
- **Stale documentation retired**: removed obsolete code maps, vendored-library guides, completed plans, one-off review/test reports, and the host-specific nginx template. The frontend container's nginx configuration remains supported.

### Changed
- **Event-driven ACP supervision**: chat delegation now wakes its originating conversation for terminal results, questions/approval and new stalls, without progress-polling model turns. Default status/list responses omit transcripts and repeated plans; `acp_get_result` provides task/turn-scoped, paginated evidence, input and error reads. Stream previews and metadata are bounded; generic output uses private temporary capture until exact result storage, and verified Claude native transcripts preserve final evidence and historical-turn boundaries. Workflow-owned routing, cancellation and strict publication evidence checks remain intact.
- **ACP review corrections**: automatic notifications use the active conversation and acknowledge only successful queue delivery. Native evidence reconstructs all blocks of the final logical assistant message, matches Claude's Unicode and long-path project encoding, and reads large JSONL records in bounded chunks. The backend reader preserves the existing Claude host-volume default instead of switching user data directories.
- **ACP continuation and evidence safety**: HTTP, heartbeat and object-agent continuations share a per-conversation execution gate; object-agent callbacks resume their owning protocol thread. Plain plan approval keeps context, and native evidence identity comes from correlated root SDK messages rather than the public ACP ID. Incomplete/corrupt transcripts cannot promote earlier prose or strand a task; sealed byte ranges and block verification preserve historical reads without rescanning future turns. Liveness remains a passive process/listener check, not a model-response probe.
- **Faster deploy image builds**: CI builds images on the self-hosted runners' host Docker daemon and reuses its local layer cache instead of round-tripping a GitHub Actions cache and exporting/loading image tarballs. The runtime and backend images install Python dependencies before copying source, and the per-commit `GIT_COMMIT` build arg is declared last, so a source-only change rebuilds in seconds rather than reinstalling every dependency.
- **Parallel CI tests**: the backend and runtime pytest suites run with four `pytest-xdist` workers, cutting the runtime suite from about 96 s to 38 s and the backend suite from about 54 s to 26 s locally.
- **Operational file logging**: the backend now writes split rotating stdout/stderr files under `logs/backend/`, matching the runtime's `logs/progena/` files; Docker logs rotate at the same 10 MiB × 5 policy. Each backend request is logged once, by the `API request completed` line with method, path, status, duration and request id; the separate request-start line and uvicorn's duplicate access line are gone. Runtime and backend log timestamps are UTC. The Logs API normalizes both plain-text and JSON timestamps to UTC instants with `Z`, including zone-less UTC timestamps, so display and date filtering agree.
- **Timezone model**: UTC is the storage, API, logging, shell, and container-clock timezone; browser-local time renders instants. User preferences define wall-clock meaning, and are copied into new schedule entries and workflow cron triggers. Legacy unstamped entries fall back to the current preference, then UTC. Every agent model call receives the user's timezone and local date (date-level, so the provider prompt cache stays valid); exact-time guidance names `current_time` only when available, `date -u` for shell-enabled delegates, and requests a caller-supplied timestamp for tool-less model calls. `PROGENA_TIMEZONE` and container `TZ` are removed.
- **Date-time boundaries**: Logs calendar filters now query complete browser-local days across DST, with UTC API boundaries and microsecond-inclusive ends. Legacy server timestamps are normalized at heartbeat, session, workflow, and task boundaries; cron payload instants remain UTC with a separate wall-clock zone. Task recency and routine lifecycle ordering compare instants rather than timestamp strings.
- **File-only operational logs**: retired database-backed operational log rows. Runtime and backend operational events now use the shared rotating files, and tool-call durations are checkpointed on their `ToolMessage` for chat history.
- **glibc arena cap**: the `progena` and `progena-backend` containers set `MALLOC_ARENA_MAX=2`, so memory freed after large transient conversation histories is reused across threads instead of being retained in per-thread malloc arenas.
- **Runtime, backend and Claude memory**: the `progena`, `progena-backend` and `progena-agent-claude` container limits are 4 GiB after production cgroup OOM kills at the old limits. Reservations and other service limits are unchanged. The Progena runtime image installs ripgrep so Deep Agents grep uses `rg` instead of its Python fallback.
- **Claude ACP update**: the Claude container pins `@agentclientprotocol/claude-agent-acp` 0.99.0 (previously 0.93.0), the latest stable release at update time.
- **Operation correlation header**: finite browser requests now use `X-Operation-Id`; JSON/SSE `request_id` correlation fields are unchanged.
- **Activity-only chat filters**: inline All, Tools, Plans, Reasoning, Delegations, Errors, and Debug chips control activity without hiding messages, answers, attachments, or images. Errors directly controls failed tools/delegations independently of their activity category. All restores activity and Errors on, Debug off. No Errors only preset, extra switch, or Advanced menu.
- **CI runs on pull requests**: the backend, Progena and frontend test jobs now also run for pull requests into `main` from branches in `tamaw/progena`, on the existing self-hosted runners. Fork PRs are skipped, and image builds and deployment remain `main`-only.
- **Deep Agents 0.7 runtime alignment**: upgraded to the 0.7.30 series with tested LangChain/LangGraph dependency floors. Kept todo support explicit, retained the existing non-delete filesystem tool set, blocked recursive deletion at read-only mounts, migrated capped/scoped grep, and removed obsolete backend aliases.
- **Workflow data-exposure controls**: deployment failures no longer dump application logs or unrelated containers into public Actions output. Added hosted, redacted contribution secret scanning with verified Gitleaks assets and trusted configuration/ignore handling; documented exact-action allowlists and 14-day log/artifact retention.

- Workflow validation: `$defs` survive extract schema inference and typed template inputs/outputs (`inputs: {flow: workflow}`); a `string` output connects to a `["string", "null"]` input (editor and backend); `true` → `1` counts as a changed field and no longer matches an event filter on `true`; malformed `filter_fields` and non-string front matter keys are validation errors instead of 500s; `workflow_run` documents accept `source: "cron"`.
- Progenitor can save workflows whose steps reference prompt documents.
- Workflow editor: `false`/`0`/`""` data values, saved node sizes, schema edits (now enabling Save), Configure/Unpack after applying JSON, Cut on an Unpack input, and Unpack fields of palette-added nodes all behave like other edits; the node options dialog scrolls instead of clipping.
- Quick chat closed mid-reply and reopened after it finished shows the reply instead of "Thinking" forever; a failed agent-roster fetch is retried on reconnect.
- Prompt/profile saves time out 15s after acknowledgement even while other updates arrive, and a save cancelled by a disconnect can't report its error on the next selection.
- Telemetry exception handlers now log at DEBUG level instead of silently passing
